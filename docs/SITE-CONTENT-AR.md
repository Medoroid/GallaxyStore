# نظام التحكم بصفحات الموقع من الأدمين (بنرات وأقسام)

> **تاريخ الإضافة:** 8 نوفمبر 2026
> **الحالة:** كود كامل ومختبَر — بانتظار تطبيق الـ migration على قاعدة البيانات

## نظرة عامة

نظام محتوى يسمح للأدمين بإضافة وتعديل **بنرات (Banners)** و**أقسام (Sections)** تظهر في مناطق محددة من صفحات الموقع (الصفحة الرئيسية حالياً)، مع:

- ترتيب يسحب-وإفلات (أعلى/أسفل) لكل منطقة.
- نشر/إيقاف فوري (`is_active`).
- جدولة زمنية اختيارية (`starts_at` / `ends_at`).
- رفع صور أو لصق روابط خارجية.
- تسجيل كل عملية في `admin_audit_log`.
- قراءة عامة آمنة عبر RLS (الصفوف غير المنشورة أو منتهية الجدولة لا تظهر إطلاقاً للزوار).

## المناطق (Zones)

| القيمة | الاسم في الواجهة | يظهر في |
|---|---|---|
| `top_strip` | Top strip | شريط علوي رفيع أعلى الهيرو (بنرات فقط) |
| `after_hero` | Below hero | تحت قسم الهيرو |
| `mid_page` | Mid page | بعد قسم المنتجات المميزة |
| `before_footer` | Before footer CTA | قبل قسم الدعوة الأخير |

## أنواع الأقسام (Section types)

| النوع | الوصف |
|---|---|
| `rich_text` | عنوان + نص (يُعرض بطاقة نصية) |
| `image_text` | صورة + نص بجانب بعضهما |
| `cards` | شبكة حتى 8 بطاقات (عنوان + نص + رابط + صورة اختيارية) |
| `cta` | بطاقة دعوة لاتخاذ إجراء بتدرج لوني |

## كيفية التفعيل (خطوات مطلوبة منك)

> **ملاحظة:** أداة `execute_sql` المتاحة لديّ تعمل بصلاحية قراءة فقط، لذا لا أستطيع تنفيذ الـ DDL على الإنتاج مباشرة. الملف مُعدّ وآمن للتكرار (`IF NOT EXISTS` / `drop policy if exists`).

1. افتح **Supabase → SQL Editor**.
2. الصق محتوى:
   `supabase/migrations/20261108130000_site_content_banners_sections.sql`
   واضغط Run. (يمكن تنفيذه أكثر من مرة بأمان.)
   - أو عبر CLI: `supabase db push` — مع مراعاة تحذير
     `docs/DATABASE-INTEGRITY-REPORT.md` §7 حول سلسلة الـ migrations.
3. تحقق من الأمان بعد التنفيذ: `get_advisors` (security) — يجب ألا تظهر مشاكل جديدة.
4. حدّث الأنواع: `generate_typescript_types` وأعد توليد `lib/database.types.ts`.
5. اختبار الظهور: من الأدمين → Content → أنشئ بنرا في "Top strip" ثم افتح الرئيسية.

**قبل التطبيق:** الموقع يعمل كالمعتاد تماماً — مكوّن `ContentZone` يفشل بصمت (بدون أخطاء) طالما الجداول غير موجودة.

## قواعد الأمان

- **القراءة العامة:** RLS يسمح فقط بصفوف `is_active = true` وداخل نافذة الجدولة.
- **الكتابة:** عبر الخادم بـ service role فقط (`verifyAdmin` أولاً في كل طلب) + سياسة `is_admin()` كطبقة إضافية للعميل المصادق عليه.
- **التحقق:** نفس القواعد في API وفي قيود `CHECK` في قاعدة البيانات (المصدر الواحد `lib/site-content.ts`).
- **الروابط:** تُقبل `https://` و `http://` ومسارات تبدأ بـ `/` فقط (يمنع `javascript:`).
- **الصور:** أنواع وحجم محدودة (5MB) — نفس مكتبة التحقق الخاصة بصور المنتجات.
- **التدقيق:** كل إنشاء/تعديل/حذف يُسجَّل في `admin_audit_log`.
