## 2. Storage policies (19 relevant, all `authenticated` except public reads)

| Bucket | Policies | Access model |
|---|---|---|
| `design-uploads` | owner insert / owner-or-admin select, update, delete | private, ownership checked on path |
| `design-previews` | admin insert / update / delete | preview generated by admin flow |
| `mockup-assets` | admin insert / select / update / delete | private admin catalog |
| `site-banners` | public read + admin insert / update / delete | public storefront banners |
| `theme-assets` | public read + admin insert / update / delete | public theme assets |
| `custom-print-designs`, `payment-receipts`, `product-images`, etc. | pre-existing policies preserved | unchanged |

No policy grants write access to `anon`.

## 3. Path conventions (enforced by policy expressions)

- `design-uploads/<auth.uid()>/…` — owner-scoped.
- `site-banners/<name>` and `theme-assets/<theme>/<asset>` — admin-managed, public read.
- `mockup-assets/<template>/…` — admin-only.
- `payment-receipts/<order>/…` — private, linked to payment records.

## 4. Storage tests

Integration tests exercise storage-backed flows (design upload/rollback, product image upload rollback, gallery), all passing. A dedicated storage-RLS role matrix is recommended on Staging with real anon/vendor/admin JWTs.
